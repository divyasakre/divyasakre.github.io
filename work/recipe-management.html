Recipe Management System for 68 PLC tire machines

A tire plant edited machine recipes by hand on SCADA screens. I led the team that centralized them, so a recipe now reaches the machine with one barcode scan.

The problem

The plant ran about 68 PLC tire machines, and their recipes lived in different places with no single source of truth. To check or change a recipe, shop-floor staff edited values by hand in SCADA. Each change took about 8 minutes and typing errors were common.

What we built

  • Central recipe library with master and child recipes, version history and per-machine recipe rules, so a machine only accepts the recipes it should run.
  • Approval workflow with JWT role-based access and audit logs, so unapproved recipes never reach a machine.
  • Barcode upload that I built on my own: a web page running in Chrome on handheld Android scanners. Operators scan a code and the right recipe is sent to the machine.
  • Machine connectors over OPC UA, Modbus TCP and MQTT that push recipes to the PLCs and receive production alerts back, giving every tire a unique code.

My role

  • Led a team of 4: planned weekly sprints and assigned backlog items.
  • Wrote the design documentation (architecture, database schema and UI plan) and worked with the client to define the data and APIs their machines would exchange.
  • Reviewed my team's code on GitHub before every merge.
  • Trained shop-floor workers to use the system in their daily work.
