Data foundation for a fundraising analytics platform

CauseFleet builds a fundraising AI analytics platform that helps nonprofits understand their donors. I redesigned its data model, moved the services onto it and loaded the first client's real data.

The problem

The platform kept every donor in one flat table, which couldn't hold real CRM and accounting data. The dashboards ran on placeholder numbers, and the first nonprofit client was waiting to see their own data.

New data model

  • Designed a new PostgreSQL donor schema and its ERD: one core table plus 7 related and 8 lookup tables.
  • Shipped it through Flyway migrations V4–V7, including client contact types and income-channel data.
  • Rewrote the Java Spring Boot donor service (entities, DTOs, mappers, repositories, services) and its batch processors to match, added REST endpoints and fixed refresh-token rotation in user management.

Analytics & KPIs

  • Rebuilt most dashboard KPI calculations in the FastAPI analytics service: one shared definition per KPI, a period label on every tile, and a fix for retention showing 0%.
  • Added a KPI snapshot endpoint, new Redis-cached results that recompute when empty, and nightly jobs.

Onboarding the first client

  • Imported 63K donors and 42K gifts through a 6-step RabbitMQ import, fixed duplicate-ID bugs, and replaced placeholder data across four dashboards.
  • Analyzed gaps in the client's data and gave them a prioritized request list. One added field unblocks about 60% of the KPIs.
  • Reviewed the in-app import flow, found 18 issues, and wrote a 17-file client data checklist and onboarding process.

Shipping it

  • Wrote scripts to run the full stack on AWS EC2 without Docker (systemd, nginx), with a deployment runbook, and fixed Docker deployment bugs in nginx and health checks.
  • Built React features: a donor directory, a Full Year / YTD toggle, "Data pending" states and brand theming.
  • Review teammates' code before merges.
